# 小智 IoT 語音機器人（xiaozhi_iot）：最新完整系統與程式架構設計書

* **硬體核心**：ESP32-S3-N16-R8（雙核心 Xtensa LX7 @ 240MHz / 16MB Flash / 8MB Octal PSRAM）
* **開發框架**：ESP-IDF v5.3.x ～ v5.4.x（FreeRTOS + C/C++ 模組化架構）
* **架構核心理念**：雙核心硬體任務隔離、八大軟體元件解耦、四層漏斗式離線容災儲存、地雲混合運算分流

## 二、 FreeRTOS 雙核心任務隔離架構（Dual-Core Pinning）

為防止 Wi-Fi 封包重傳、TLS 握手或本地設定網頁連線阻塞高即時性的雙麥克風收音與螢幕刷新，系統在 `main.c` 啟動階段將所有 FreeRTOS 任務明確綁定至指定 CPU 核心：

```text
+-----------------------------------------------------------------------------------+
|                         ESP32-S3-N16-R8 (240MHz Dual-Core)                        |
+-----------------------------------------+-----------------------------------------+
|        Core 0：通訊與網路處理核心        |        Core 1：即時硬體與運算核心        |
|        (Protocol & Network Core)        |        (Real-Time & Audio Core)         |
+-----------------------------------------+-----------------------------------------+
| 1. Wi-Fi 驅動與 LWIP TCP/IP 協定棧      | 1. Audio Capture Task (最高優先權)       |
| 2. Net Manager 狀態機任務               |    - 雙 INMP441 I2S DMA 收音 + AEC 降噪 |
|    - 模式 0: 關閉射頻                   |    - ESP-SR WakeNet 喚醒與離線指令辨識  |
|    - 模式 1: Server WebSocket/HTTP 客戶端| 2. Audio Playback Task                  |
|    - 模式 2: Local Config Web Server    |    - MAX98357 I2S 串流/SD 卡音樂播放    |
| 3. Chronological Sync 歷史補傳任務      | 3. Sensor & Storage Task                |
|    - 依序讀取 SD 卡 -> EEPROM -> Server |    - 定時讀取 DHT22 / GY-30 / DS3231    |
|                                         |    - 寫入 PSRAM 快取 & 離線黑盒子分流   |
|                                         | 4. OLED UI & Alert Task                 |
|                                         |    - 畫面輪播、自動調光、儲存臨界警告   |
+-----------------------------------------+-----------------------------------------+
                 ▲                                            ▲
                 |           FreeRTOS 跨核心安全溝通橋樑        |
                 +---- [ EventGroup / RingBuffer / Mutex ] ---+
```

## 三、 匯流排共享與電氣／防衝突保護設計（`board_config`）

硬體端採用洞洞板＋裸銅線佈局，軟體端必須配合實體線路建立嚴格的匯流排互斥鎖（Mutex），杜絕多任務同時存取導致的死鎖或雜訊干擾：

| 匯流排類型 | 掛載周邊模組 | 軟體防衝突與硬體保護機制 |
| :--- | :--- | :--- |
| **I2C 共享匯流排**<br>（SDA / SCL） | 1. `OLED 0.96"` (`0x3C`)<br>2. `GY-30 BH1750` (`0x23`)<br>3. `DS3231 RTC` (`0x68`)<br>4. `AT24C256 EEPROM` (`0x50`) | 建立全域 **`xI2cBusMutex`**。任何任務讀寫螢幕、感測器、時鐘或 EEPROM 前必須先取得鎖，操作完畢立即釋放。 |
| **SPI 匯流排**<br>（MOSI/MISO/CLK/CS） | **SD 卡模組**（`/sdcard/`） | 建立全域 **`xSpiSdMutex`**。當播放本地 MP3（如《稻香》）與觸發「EEPROM 轉存 SD 卡」同時發生時，以小封包交錯取得鎖，避免音樂卡頓；發送端串接 `47Ω` 阻尼電阻。 |
| **I2S 雙通道匯流排** | **Rx**：2x `INMP441`（65mm 間距，硬體 L/R 分離）<br>**Tx**：`MAX98357` + 3W 8Ω 喇叭 | 獨立 I2S0（麥克風）與 I2S1（喇叭）外設通道，發送端串接 `47Ω` 阻尼電阻；回傳播放參考訊號給 `ESP-SR AEC` 執行硬體級回音消除。 |
| **1-Wire 單線** | `DHT22` 溫濕度感測器 | 讀取時序對中斷敏感，讀取瞬間使用 `portENTER_CRITICAL` 短暫屏蔽單核中斷（約數毫秒），確保校驗碼 100% 通過。 |

## 四、 核心資料結構定義（16-Byte 統一感測封包）

為了讓 `PSRAM`、`AT24C256`、`SD 卡` 與 `Server` 之間能無縫搬運資料，所有模組感測紀錄統一封裝為 **固定 16 Bytes 二進位結構**（結構緊湊、無對齊浪費、自帶完整性校驗）：

```c
// 固定 16 Bytes 感測器數據封包（供 PSRAM / EEPROM / SD 卡共用）
typedef struct __attribute__((packed)) {
    uint32_t timestamp;     // 4 Bytes: DS3231 提供的 Unix 時間戳記（精準至秒）
    int16_t  temperature;   // 2 Bytes: 溫度 × 10（例如 253 代表 25.3°C）
    uint16_t humidity;      // 2 Bytes: 相對濕度 × 10（例如 615 代表 61.5%）
    uint32_t lux;           // 4 Bytes: GY-30 光照度（單位：lux）
    uint16_t status_flags;  // 2 Bytes: 感測器異常旗標 / 當時網路模式紀錄
    uint16_t crc16;         // 2 Bytes: 單筆資料 CRC16 校驗碼（防壞軌或匯流排雜訊）
} sensor_record_t;          // 總計：4 + 2 + 2 + 4 + 2 + 2 = 16 Bytes
```

## 五、 四層漏斗式離線容災儲存與雙重預警架構

系統將記憶體與儲存介質分為四個層級，兼顧高速運算、晶片壽命保護與長期斷網零遺失：

```text
[感測器定時採集: DHT22 + GY-30 + DS3231]
                 │
                 ├──► (1) 【第 1 層：8MB Octal PSRAM】 (永遠寫入)
                 │        • 環形緩衝區保留「最近 1 小時（預設）」數據
                 │        • 地端毫秒級計算均溫/極值/趨勢 -> 供 OLED 顯示 & 節省 LLM Token
                 │
                 └──► (判斷網路狀態：是否處於模式 0 離線 / 斷網？)
                          │ (是，未連上 Server)
                          ▼
                      (2) 【第 2 層：AT24C256 EEPROM】 (32KB 空間分區隔離)
                          • [0x0000 ~ 0x03FF] (1KB): 系統設定區（Wi-Fi/閥值/指標，永不誤刪）
                          • [0x0400 ~ 0x7FFF] (31KB): 感測器黑盒子區（可存約 1,984 筆）
                          │
                          ├──► 使用率達 80% ──► 觸發【一級預警】：OLED 警告 + 提示音
                          │
                          └──► 使用率達 100%（使用者仍未開 Wi-Fi）
                                   │
                                   ▼
                      (3) 【第 3 層：SPI SD 卡長期緩衝】 (/sdcard/sensor_offline/)
                          • 依 DS3231 日期分檔（如 20261119.bin），使用 "ab" 檔尾附加寫入（嚴禁覆寫）
                          • 執行 fflush() + fsync() 強制落盤 + CRC32 回讀驗證
                          • 驗證 100% 通過後 ──► 【精準淨空 AT24C256 感測器黑盒子區】
                          • 監控 SD 卡剩餘空間 < 100MB ──► 觸發【二級嚴重預警】：OLED 閃爍 + 語音警告
```

### 關鍵原子操作規範（Verify-Before-Purge）
1. **防覆寫機制**：SD 卡寫入一律以當日日期命名（`YYYYMMDD.bin`），同日多次滿載自動接在檔案後方往下新增，跨日自動開新檔。
2. **先驗證後淨空**：`AT24C256` 轉存至 SD 卡時，必須等 `fsync()` 完成且重新從 SD 卡讀出該區塊比對 `CRC32` 完全一致後，才允許將 `AT24C256` 內**僅限感測器資料區**的讀寫指標歸零並抹除（保留系統設定區）。

## 六、 三態互斥網路狀態機與時間順序補傳（`net_manager`）

系統透過實體按鍵或語音指令在三種互斥狀態間切換，確保同一時間僅有一種網路角色運行：

### 1. 三種運行模式定義
* **模式 0：純離線模式（Offline Mode）**
  * 徹底關閉 Wi-Fi 射頻（零射頻干擾、最低功耗）。
  * OLED 正常輪播即時與近 1 小時 PSRAM 統計；SD 卡可播放本地音樂；感測數據寫入 `AT24C256`（滿載自動轉存 SD 卡）；`ESP-SR MultiNet` 支援「開啟 Wi-Fi」、「播放音樂」、「現在溫度」等離線固定指令。
* **模式 1：標準聯網模式（Online Mode）**
  * 連線路由器並建立與外部 Server 的通訊通道。
  * 開啟雲端自然語音對話（STT + LLM + TTS）與中央氣象署預報查詢；地端僅傳送 PSRAM 算好的簡短統計摘要，大幅降低 LLM Token 成本。
  * 連線成功後立即啟動**時間順序歷史補傳任務**。
* **模式 2：本地網頁設定模式（Local Config Web Mode）**
  * 優先透過區域網路 IP 啟動 HTTP Web Server；若路由器連線失敗，自動切換為 ESP32 自建 Wi-Fi AP 熱點。
  * 提供網頁表單設定 Wi-Fi 帳密、感測採樣週期、PSRAM 統計區間、EEPROM／SD 卡警告臨界值與 OLED 自動調光參數。

### 2. 開啟 Wi-Fi 後的「嚴格時間順序」補傳流程
切換至模式 1 並連上 Server 後，補傳引擎鎖定儲存互斥鎖，依照「資料產生時間由舊到新」執行三階段同步：

1. **階段 A（最舊資料）：清空 SD 卡歷史批次檔**
   * 掃描 `/sdcard/sensor_offline/`，依檔名日期由小到大排序（如 `20261118.bin` $\rightarrow$ `20261119.bin`）。
   * 逐檔分批（每包 50 筆）傳送至 Server；收到 Server 針對該檔案的完整 `ACK` 確認後，立即刪除該 `.bin` 檔，再處理下一個檔案。
2. **階段 B（較新資料）：清空 AT24C256 殘留黑盒子資料**
   * 確認 SD 卡 `/sensor_offline/` 目錄已全數清空後，讀取 `AT24C256` 內尚未轉存的剩餘感測數據（由最舊指標至最新指標）。
   * 分批傳送至 Server 並取得 `ACK` 後，淨空 `AT24C256` 感測器資料區。
3. **階段 C（最新資料）：恢復即時串流**
   * 解除補傳鎖定，恢復定時即時數據上報與遠端語音互動。

## 七、 八大模組對外介面（API）設計規範

各模組透過清晰的標頭檔（`.h`）對外暴露功能，隱藏內部硬體暫存器細節：

| 模組名稱 | 核心對外函式介面（Public API） | 負責任務與關鍵實作細節 |
| :--- | :--- | :--- |
| **`board_config`** | `board_init_all()`<br>`board_i2c_lock()` / `unlock()`<br>`board_spi_lock()` / `unlock()` | 初始化 GPIO、I2C、SPI、I2S 與所有 FreeRTOS Mutex / EventGroup；執行開機硬體自檢（印出 Flash/PSRAM 容量）。 |
| **`audio_engine`** | `audio_engine_start()`<br>`audio_play_stream()`<br>`audio_stop_playback()` | 在 PSRAM 配置音訊 DMA 緩衝區；執行雙麥克風波束成形與 AEC；分發喚醒事件與離線命令詞 ID。 |
| **`sensor_hub`** | `sensor_hub_start()`<br>`sensor_get_latest(&rec)`<br>`rtc_set_time()` / `rtc_get_unix()` | 定時輪詢 DHT22 與 GY-30；從 DS3231 讀取精準時間戳；聯網時支援透過 NTP 自動校準 DS3231。 |
| **`psram_cache`** | `psram_cache_init(hours)`<br>`psram_cache_push(&rec)`<br>`psram_cache_get_stats(&stats)` | 使用 `heap_caps_malloc(..., MALLOC_CAP_SPIRAM)` 建立環形陣列；O(N) 毫秒級計算區間均溫、極值與斜率趨勢。 |
| **`eeprom_blackbox`** | `eeprom_init()`<br>`eeprom_push_record(&rec)`<br>`eeprom_get_usage_percent()`<br>`eeprom_export_and_purge()` | 管理 AT24C256 雙分區；達 80% 觸發警告事件；達 100% 呼叫 `sd_media` 寫入並完成 CRC32 驗證後精準淨空。 |
| **`sd_media`** | `sd_mount()`<br>`sd_play_mp3(path)`<br>`sd_append_offline_batch(buf, len)`<br>`sd_get_free_mb()` | 掛載 FAT32 SD 卡；管理音訊播放；提供 `Append + fsync + CRC32` 驗證寫入；定期檢查剩餘容量是否 `< 100MB`。 |
| **`oled_ui`** | `oled_ui_start()`<br>`oled_set_alert(alert_type, msg)`<br>`oled_update_brightness(lux)` | 依 GY-30 照度動態調整 OLED 對比度；輪播環境數據與統計圖示；優先置頂顯示 EEPROM/SD 儲存臨界警告橫幅。 |
| **`net_manager`** | `net_set_mode(mode_t mode)`<br>`net_get_mode()`<br>`net_trigger_sync()` | 管理模式 0/1/2 互斥切換；執行 SD 卡 $\rightarrow$ EEPROM 時間順序補傳；處理 Server 指令與 CWA 天氣查詢轉發。 |
